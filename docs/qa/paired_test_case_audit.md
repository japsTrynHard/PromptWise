# PromptWise paired-case audit

Current acceptance reference: ACTIVITY 1 – Finals Test Scenario and Test Cases (1).pdf (53 pages; 100 cases, 50 positive and 50 negative). Authentication is excluded by the test specification. This matrix began against an earlier 52-page paired version; use the dated finals reports for current execution evidence and limitations.

## Result and limits

The attached specification is the acceptance reference, not evidence that its cases have already passed. All 100 IDs are mapped below. Local fixture tests and source-contract checks are distinct from a live end-to-end pass. No production data was modified, and the new SQL migration has not been applied to a remote database.

Local validation results are recorded below after the final run. Automated evidence covers the behavior named in each row, not every external precondition. Rows marked Reviewed have source inspection only for at least one essential part. Every case still requiring a deployed service, real browser/OS behavior, or device playback is explicitly called out.

## Fixes made

- Lesson save failure now keeps the learner on the lesson with feedback, and retry resends pending progress without another completion entry. Missing linked quiz gives actionable feedback.
- Lesson-linked checks use focused mode. The client rejects unrelated returned topics, and migration 20260922080000_focused_lesson_practice.sql limits focused SQL selection to that topic. General adaptive checks retain their mixed-topic behavior.
- Coach Clear invalidates old in-flight requests; concurrent reviews are blocked; whitespace validation is consistent.
- Quiz Retry stays disabled while the previous attempt is saving.
- Diagnostic rejects out-of-range choices as well as missing answers.
- Awareness category changes supersede stale requests, clear old-category cards, and release loading flags. Duplicate/invalid source rows are excluded; failed or malformed refreshes cannot claim success.
- Quick Check requires the requested unique case count. Leaving does not wait for a stalled cleanup request.
- Image source responses require the requested unique round count; repeated Next cannot skip a round; speculative image loading does not raise duplicate unhandled errors.
