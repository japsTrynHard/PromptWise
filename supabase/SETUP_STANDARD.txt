PROMPTWISE SUPABASE - CLEAN STANDARD SETUP
===========================================

This folder is intentionally kept simple:

supabase/
  config.toml
  functions/
  migrations/
  CURRENT_DB_ONE_RUN.sql
  SETUP_STANDARD.txt

WHAT WAS REMOVED
----------------
- supabase/.temp/
  Local Supabase CLI state. It is machine-specific and is regenerated by `supabase link`.
- Old PHASE7/PHASE8/PHASE9 root SQL helpers, verification queries, and readme files.
  They were duplicate/manual development artifacts and are not needed by the running app.

DO NOT DELETE
-------------
- functions/
- migrations/
- config.toml

The migrations folder is the database change history. Keep it in Git.

CURRENT PROMPTWISE DATABASE - RECOMMENDED SETUP
-----------------------------------------------

1. Open a terminal at the Flutter project root.

2. If this PC is not currently linked to the Supabase project, link it once:

   npx supabase link --project-ref xqkhcuakymymmivgqpen

   The removed `.temp` folder will be recreated automatically.

3. Run CURRENT_DB_ONE_RUN.sql ONE TIME in:
   Supabase Dashboard -> SQL Editor -> New query -> paste all -> Run

   This is an idempotent finalizer for the EXISTING PromptWise database.
   It finalizes the current Phase 9 AI Awareness / Verify database settings,
   AI-only feed rules, trusted sources, learner feed RPC, cleanup, and scheduler.

4. Deploy the current Edge Functions:

   npx supabase functions deploy awareness-feed --use-api --no-verify-jwt
   npx supabase functions deploy content-automation --use-api --no-verify-jwt
   npx supabase functions deploy verification-media --use-api --no-verify-jwt
   npx supabase functions deploy promptwise-integrations --use-api --no-verify-jwt

5. Test Flutter:

   flutter analyze
   flutter test

6. Run the app with your normal SUPABASE_URL and
   SUPABASE_PUBLISHABLE_KEY dart-defines.

IMPORTANT
---------
- Do NOT put the Supabase service-role key in Flutter.
- Existing Supabase secrets stay on the Supabase project and do not need to be
  copied into this folder.
- CURRENT_DB_ONE_RUN.sql is for the CURRENT existing PromptWise database.
  It is not a complete from-zero bootstrap for a brand-new empty Supabase project.
- For future schema changes, the standard approach is: create a new migration
  under `supabase/migrations/` instead of adding more PHASE*_ONE_RUN.sql files
  to the root.

STANDARD FUTURE WORKFLOW
------------------------
Create a migration:
  npx supabase migration new short_change_name

Edit the generated SQL in:
  supabase/migrations/<timestamp>_short_change_name.sql

Apply migrations to the linked project:
  npx supabase db push

Deploy only the Edge Function(s) whose code changed.

That keeps the Supabase folder clean and reproducible.
